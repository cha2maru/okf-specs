# 要件

## 定義

要求を実現するために、システムが果たすべき振る舞い。「**〇〇をする**」で表現する。

## 主語

主語は原則として**システム**とする。例外はありうる。

## 表現形式のまとめ

| 層 | 表現 | 主語 |
|---|---|---|
| [要望](/concepts/wish.md) | 〇〇したい | 発言者 |
| [要求](/concepts/requirement.md) | 〇〇ができる | 利用者・業務 |
| 要件 | 〇〇をする | システム |

## 受入基準

- OKF の要件には受入基準の **ID** を持たせる。将来、受入基準とテストのリレーションを機械的に確かめるために使う。
- 受入基準の**文章を OKF に書いてもよい**。書かない場合は SDD の Spec（または要件定義書）に書く。
- 受入基準を必須にするか（例：機能要件は 1 件以上）は未決（未決事項 #33）。

```yaml
acceptance:
  - { id: AC-006-1, text: 異常を含む点検結果を送信すると拠点の管理者にメールが届く }   # text は任意
  - { id: AC-006-2 }
```

## リレーション

- [要求](/concepts/requirement.md) ⇔ 要件：多対多。新しい要求が**既存の要件**に対応することもある。
- 要件 → [契約](/concepts/contract.md)：要件は**できる限り具体的な契約**を指す。機能要件は機能契約へ、非機能要件は非機能契約へ紐づく。
- 要件から開発オブジェクトへ直接は紐づけない。**必ず契約を経由する**。

## 留意点

既存の要件に新しい要求を紐づけると、その要件は複数の要求を同時に満たす必要がある。要件の変更はそれらすべての要求に影響する。
