# 質問の仕方

裁定の質問は「それが何であるか」を確定するためのもの。設計のための質問はしない。

## 聞くこと

| 目的 | 質問の例 |
|---|---|
| 誰が | それを使う（困っている）のは誰ですか？ 点検者ですか、管理者ですか？ |
| なぜ | それができないと、いま何が困りますか？ |
| いつ・どこで | どんな場面で必要になりますか？ |
| 新しいか、壊れているか | 以前はできていましたか？ いつから起きていますか？ |
| したいのか、知りたいのか | できるようにしたいですか、それともできるかどうかを知りたいですか？ |
| 範囲 | 全員に必要ですか、一部の人だけですか？ |
| 非機能のにじみ（1 問まで） | 止まると困る時間はありますか？ 他の人に見られると困りますか？ |

## 聞かないこと

- 解決策・設計：「CSV と Excel のどちらがいいですか？」「ボタンはどこに置きますか？」「どの画面に出しますか？」（okf-breakdown 以降で扱う）
- 誘導：「〇〇機能があれば解決しますよね？」
- 一度に多くの質問（1 回に 2〜3 問まで）

## バグ報告で残すこと

症状、発生した日時、端末・アプリの種類、操作の手順、毎回起きるか。分かった範囲でよい（調べるのは今後の課題）。
