# 種別ごとの本文の節

必須の節は必ず書く（決められないなら【要確認】付きの案）。（任意）の節は該当するときだけ書く。

| 種別 | 必須の節 | 任意の節 | 書かないこと |
|---|---|---|---|
| API | 概要、認証・認可、入力の業務制約、処理、エラー、排他・トランザクション・冪等性 | 方式、検索条件・ページング、外部呼び出し、出力、ログ | 入出力の型・桁（契約の OpenAPI に書く） |
| 画面 | 概要、画面項目、操作・イベント、画面遷移、入力チェック、メッセージ、権限 | レイアウト、状態表示、API エラー時の対応、二重送信防止・自動更新・オフライン | API の入出力（契約に書く） |
| イベント処理 | 概要、起動契機・前提、入力、処理、再試行、冪等性・重複排除、エラー、ログ・監視 | 出力、多重度・順序、メッセージ | 配送保証・DLQ の有無（メッセージ契約に書く） |
| バッチ・バックグラウンド処理 | 概要、起動契機、入力、処理、出力・状態遷移、再試行・冪等性、エラー | 時間枠・性能、中断・再開・再実行、多重度・排他、メッセージ、ログ | |
| オンライン処理 | 概要、入力・出力、処理、エラー | 排他・トランザクション、ログ | |
| テーブル | 概要、項目定義、インデックス・制約、件数見込み、保持・削除 | 状態値・コード値、状態遷移、排他、論理削除、パーティション | エンティティ間の関連（契約の ER 図） |
| ファイル | 概要、形式、保持・世代管理 | 件数・容量見込み、アクセス制御・暗号化 | 置き場所・キーの形式（契約のキー規約） |
| IaC リソース | 概要、関連するリソース、設定値（根拠つき）、セキュリティ、バックアップ・保持、監視 | 動かすアプリ、冗長化・配置、アプリに渡す値 | 接続情報の値の定義（接続情報の契約） |

## 書き方の要点

- **処理**：番号付きの手順。読む・書くデータは `uses` と一致させる。業務ルール（判定の条件など）を具体的に書く。
- **エラー**：条件・応答（ステータスや画面の振る舞い）・メッセージ ID・文言。5xx や通信エラーも含める。
- **画面項目**：エリアごとに表を分けてよい。データ元（API の項目、端末内データ）を書く。
- **メッセージ**：ID は共通方針の体系に従う。
- **他の開発オブジェクトの取り決め**：1 行と ID で触れるだけ（例：「サイズ上限は OBJ-040101 で 10MB」）。
- **受入基準との対応**：要件の受入基準を満たす手順・エラーがあるかを確かめる。
