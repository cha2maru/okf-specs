## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理者は異常のある点検結果を発生後すぐに知ることができる

管理者は異常のある点検結果を発生後すぐに知ることができる。

**Use Case**（補足）：

1. 異常通知メールを受け取る
2. メールのリンクからダッシュボードを開く（画面：OBJ-030101 拠点進捗画面）

**Acceptance Scenarios**：

*SPC-006 クラウドは異常ありの点検結果を受信したら拠点の管理者へメールで通知する*

- **Given** 拠点 A の管理者としてメールアドレスが登録されている
- **When** 拠点 A の設備で「異常」を含む点検結果を送信する
- **Then** 拠点 A の管理者に、設備名・異常項目・ダッシュボードへのリンクを含むメールが届く
- **Then** 異常を含まない点検結果ではメールが送られない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**（SPC-008）：クラウドは異常通知を点検結果の受信から 5 分以内に送信する
  - **結果** 異常を含む点検結果の受信時刻から、メール送信 API の受付時刻までが 5 分以内
  - 補足：メールが受信箱に届くまでの時間は外部サービス依存のため、基準は「送信 API の受付」までとする
