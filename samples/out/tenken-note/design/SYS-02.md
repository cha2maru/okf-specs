## 4. 機能詳細

### 4.1 POST /inspections（OBJ-020101）

#### 4.1.1 概要

点検結果を 1 件受け付けて保存する。異常を含む場合は異常イベントを発行する。

#### 4.1.2 関連要求・要件

- SPC-003 モバイルアプリは通信回復時に未送信の点検結果と写真を自動送信する（機能・直接）
- SPC-004 クラウドは受信した点検結果と写真を保存する（機能・直接）
- SPC-006 クラウドは異常ありの点検結果を受信したら拠点の管理者へメールで通知する（機能・利用）
- SPC-008 クラウドは異常通知を点検結果の受信から 5 分以内に送信する（非機能・配分）

#### 4.1.3 インターフェース

出典：CTR-F-001 点検API

```yaml
POST /inspections:
  summary: 点検結果を登録する
  parameters:
  - name: Idempotency-Key
    in: header
    required: true
  requestBody:
    content:
      application/json:
        schema:
          type: object
          required:
          - equipmentId
          - inspectedAt
          - items
          properties:
            equipmentId:
              type: string
            inspectedAt:
              type: string
              format: date-time
            items:
              type: array
              items:
                type: object
                properties:
                  code:
                    type: string
                  result:
                    enum:
                    - 正常
                    - 異常
                  comment:
                    type: string
  responses:
    '201': {}
    '200':
      description: 冪等キー重複時
```

#### 4.1.4 処理内容

1. Idempotency-Key で点検結果テーブルを検索し、既に存在すれば保存済みの内容を 200 で返す。
2. 入力を検証する（equipmentId の存在、items が 1 件以上）。
3. 点検結果テーブルに登録する。items に「異常」が 1 件でもあれば hasAnomaly = true。
4. hasAnomaly = true の場合、異常イベントを発行する。
5. 201 で inspectionId を返す。

#### 4.1.5 使用データ

| データ | 契約 | CRUD |
|---|---|---|
| OBJ-020401 点検結果テーブル | CTR-F-003 | CR |

#### 4.1.6 利用する契約（データ以外）

- CTR-F-008 DB接続 → コンポーネント：CMP-0402 データ基盤
- CTR-F-007 異常イベント → コンポーネント：CMP-0203 異常通知

#### 4.1.7 エラー処理

| 条件 | 応答 | メッセージ |
|---|---|---|
| 必須項目なし・形式不正 | 400 | 入力内容に誤りがあります |
| equipmentId が存在しない | 404 | 設備が見つかりません |
| イベント発行失敗 | 201 | （登録は成功扱い。発行は再試行キューへ） |

#### 4.1.8 非機能要件（配分）

- CTR-N-002 異常通知の即時性：受信から異常イベント発行まで 10 秒以内

### 4.2 PUT /inspections/{id}/photos/{n}（OBJ-020102）

#### 4.2.1 概要

点検結果に写真を 1 枚追加する。同じ n で再送された場合は上書きする。

#### 4.2.2 関連要求・要件

- SPC-003 モバイルアプリは通信回復時に未送信の点検結果と写真を自動送信する（機能・直接）
- SPC-004 クラウドは受信した点検結果と写真を保存する（機能・直接）

#### 4.2.3 インターフェース

出典：CTR-F-001 点検API

```yaml
PUT /inspections/{id}/photos/{n}:
  summary: 点検写真をアップロードする
  requestBody:
    content:
      image/jpeg: {}
```

#### 4.2.4 処理内容

1. 点検結果テーブルに id が存在することを確認する。
2. 画像を検証する（JPEG、長辺 2048px 以下）。
3. 写真ストレージにキー規約どおり保存する。

#### 4.2.5 使用データ

| データ | 契約 | CRUD |
|---|---|---|
| OBJ-020401 点検結果テーブル | CTR-F-003 | R |
| OBJ-020501 点検写真 | CTR-F-006 | C |

#### 4.2.6 利用する契約（データ以外）

- CTR-F-008 DB接続 → コンポーネント：CMP-0402 データ基盤
- CTR-F-009 写真バケット → コンポーネント：CMP-0403 ストレージ基盤

#### 4.2.7 エラー処理

| 条件 | 応答 | メッセージ |
|---|---|---|
| 点検結果が存在しない | 404 | 点検結果が見つかりません |
| 形式・サイズ不正 | 400 | 写真の形式が不正です |

#### 4.2.8 非機能要件（配分）

なし

### 4.3 GET /sites/progress（OBJ-020201）

#### 4.3.1 概要

指定月の拠点ごとの点検対象数と点検済数を返す。

#### 4.3.2 関連要求・要件

- SPC-005 ダッシュボードは拠点ごとの当月点検完了率を表示する（機能・直接）
- SPC-007 ダッシュボードは拠点進捗を 3 秒以内に表示する（非機能・配分）

#### 4.3.3 インターフェース

出典：CTR-F-004 管理API

```yaml
GET /sites/progress:
  parameters:
  - name: month
    in: query
    schema:
      type: string
      example: 2026-10
  responses:
    '200':
      content:
        application/json:
          schema:
            type: array
            items:
              type: object
              properties:
                siteId:
                  type: string
                name:
                  type: string
                total:
                  type: integer
                done:
                  type: integer
```

#### 4.3.4 処理内容

1. month 未指定の場合は当月とする。
2. 拠点ごとに、対象設備数と、当月に点検結果がある設備数を集計する。
3. 拠点名の昇順で返す。

#### 4.3.5 使用データ

| データ | 契約 | CRUD |
|---|---|---|
| OBJ-020401 点検結果テーブル | CTR-F-003 | R |
| OBJ-020402 拠点テーブル | CTR-F-003 | R |

#### 4.3.6 利用する契約（データ以外）

- CTR-F-008 DB接続 → コンポーネント：CMP-0402 データ基盤

#### 4.3.7 エラー処理

| 条件 | 応答 | メッセージ |
|---|---|---|
| month の形式不正 | 400 | 対象月の形式が不正です |

#### 4.3.8 非機能要件（配分）

- CTR-N-001 ダッシュボード応答性能：API 応答 1.5 秒以内

### 4.4 異常通知処理（OBJ-020301）

#### 4.4.1 概要

異常イベントを受け、拠点の管理者へメールで通知する。

#### 4.4.2 関連要求・要件

- SPC-006 クラウドは異常ありの点検結果を受信したら拠点の管理者へメールで通知する（機能・直接）
- SPC-008 クラウドは異常通知を点検結果の受信から 5 分以内に送信する（非機能・配分）

#### 4.4.3 インターフェース

受信するメッセージ（出典：CTR-F-007 異常イベント）

```json
{ "inspectionId": "string", "siteId": "string", "equipmentId": "string", "anomalyItems": ["code"] }
```

#### 4.4.4 処理内容

1. 異常イベントを受信する。
2. 拠点テーブルから siteId の管理者メールアドレスを取得する。
3. 件名「【点検ノート】異常検知：{設備名}」で、異常項目とダッシュボードの URL を本文に含めて送信 API を呼ぶ。

#### 4.4.5 使用データ

| データ | 契約 | CRUD |
|---|---|---|
| OBJ-020402 拠点テーブル | CTR-F-003 | R |

#### 4.4.6 利用する契約（データ以外）

- CTR-F-008 DB接続 → コンポーネント：CMP-0402 データ基盤
- CTR-F-005 メール送信 → コンポーネント：CMP-0501 メール送信API

#### 4.4.7 エラー処理

| 条件 | 対応 |
|---|---|
| 管理者メール未登録 | ログに警告を出して終了 |
| 送信 API が 5xx・タイムアウト | 指数バックオフで最大 3 回再試行。失敗したらデッドレターへ |

#### 4.4.8 非機能要件（配分）

- CTR-N-002 異常通知の即時性：イベント受信から送信 API 呼び出しまで 1 分以内（リトライ込み）
