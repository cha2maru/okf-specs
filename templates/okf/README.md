# OKF テンプレート

OKF の概念ファイルを書くときのテンプレート。`samples/out/tenken-note/manual/` の手書き設計書（SYS-01〜04、契約書）を書いて見つかった不足を反映している。

## 書き方の原則

- **フロントマター**：リレーションのチェックと検索に使う情報だけ。コメントの「必須」はチェッカーで確かめる対象（予定を含む）。
- **本文**：設計書が書けるだけの情報。節は目安で、増減してよい。該当しない節は消すか「なし」と書く（空欄で残さない）。
- **重ねて書かない**：契約（OpenAPI・ER 図など）に書いたことは開発オブジェクトに書かない。システムの共通方針に書いたことは、個々には差分だけを書く。
- **名前だけで済ませない**：本文に出てくるリソースやデータ（キュー、KMS キー、マスタなど）は、開発オブジェクトや契約として起こす。
- **他の開発オブジェクトの取り決め**は、1 行と ID で触れるだけにする（例：「サイズ上限は OBJ-040101 で 10MB」）。
- **（任意）** と付いた節は、該当しなければ消す。
- **版の履歴は本文に書かない**。改版の理由は `log.md` に書く。
- **uses** は 1 エントリ＝（契約, CRUD）の組。同じ契約でも CRUD が違えば分ける。自分の親コンポーネントが提供する契約は書かない（呼び出し元・利用者は、相手の uses から導出できる）。
- **`{}` を含む値**（パスなど）は、フロー形式の中では `"…"` で囲む。
- **検索用のフィールド**として `tags`、`resource_type`（IaC）、`resource_version`（外部 API）を使ってよい。
- 追加のリレーション（`actor`／`actors`、`disposition`、`roles`、`transitions`、`entities`、`depends_on`、`hosts`、`realizes`、配分の `amount`／`role`／`within`）は #34 で採用済み。

## 書き方の例

`examples/` に、種別ごとに書き方の違う例を置く（題材は点検ノートのほか、在庫・注文・予約・請求の架空システム）。例ごとに別の架空プロダクトとして扱っているため、例どうしで ID が重なることがある。

| 種別 | 例 |
|---|---|
| function | オンライン処理（在庫引当）、イベント処理（予約確定メール）、バッチ（月次請求）、バックグラウンド同期（点検ノート） |
| api | 登録（注文）、検索・ページング（予約一覧）、ファイルアップロード（点検写真）、外部 API 呼び出し（決済与信） |
| screen | 一覧・検索（在庫）、入力・登録（予約）、ダッシュボード（拠点進捗）、圏外対応（点検入力） |
| db | マスタ（商品）、トランザクション・履歴（予約）、NoSQL（セッション・カート）、ER 図の契約（予約DB） |
| iac | ロードバランサー、DB クラスタ、ストレージ、コンテナサービス |
| contract | OpenAPI、メッセージ定義、接続情報、キー規約、外部 API、非機能 |
