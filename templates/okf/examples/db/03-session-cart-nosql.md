# OBJ-150101：セッション・カートテーブル

> 例：NoSQL（キー・バリュー／ドキュメント型）の書き方。項目定義より先にアクセスパターンを書き、そこからキー設計・TTL を決める。RDB の「インデックス・制約」は「キー設計」に置き換える（題材：セッション／カート）

## 概要

- データストア：Amazon DynamoDB（オンデマンドキャパシティ）。テーブル名 `ec-session`。
- 1 アイテム＝1 セッション、または 1 カート。ログイン前のカートはセッションに、ログイン後は会員にひも付ける。
- RDB と違い、スキーマはアプリ側で守る。結合はしない（必要な情報は 1 回の読み取りで取れるように持つ）。

## アクセスパターン

キー設計はこの表から決めた。ここにないアクセスは想定しない（追加するときはキー設計を見直して改版する）。

| No | アクセス | 呼び出し元 | 頻度（ピーク） | 操作 |
|---|---|---|---|---|
| A1 | セッション ID でセッションを取得 | 全 API の認証処理 | 2,000 回/秒 | GetItem |
| A2 | セッションを作成・延長 | ログイン、各リクエスト | 300 回/秒 | PutItem／UpdateItem |
| A3 | セッションを削除 | ログアウト | 10 回/秒 | DeleteItem |
| A4 | 会員 ID でカートを取得 | カート画面、注文確定API | 400 回/秒 | GetItem |
| A5 | 匿名セッションのカートを取得 | カート画面（未ログイン） | 200 回/秒 | GetItem |
| A6 | カートに商品を追加・数量変更 | カート操作API | 150 回/秒 | UpdateItem（条件付き） |
| A7 | ログイン時に匿名カートを会員カートへ統合 | ログインAPI | 30 回/秒 | TransactWriteItems |
| A8 | 会員の全セッションを無効化 | パスワード変更 | まれ | Query（GSI1）＋ BatchWrite |

## キー設計

| エンティティ | PK | SK | GSI1PK | GSI1SK |
|---|---|---|---|---|
| セッション | `SESSION#{sessionId}` | `META` | `MEMBER#{memberId}`（ログイン後のみ） | `SESSION#{sessionId}` |
| カート（会員） | `CART#MEMBER#{memberId}` | `META` | | |
| カート（匿名） | `CART#SESSION#{sessionId}` | `META` | | |

- GSI1：会員 ID からセッションを引く（A8）。射影は KEYS_ONLY。
- カートはアイテム 1 つに明細を配列で持つ（明細は最大 100 件で、1 アイテム 400KB の上限に収まる）。

## 項目定義

セッション

| 論理名 | 属性名 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| セッション ID | sessionId | S | ○ | 128bit の乱数を Base64URL |
| 会員 ID | memberId | N | | ログイン後に設定 |
| 権限 | roles | SS | | |
| 作成日時 | createdAt | S | ○ | ISO 8601（UTC） |
| 最終アクセス日時 | lastAccessAt | S | ○ | 1 分以上たったアクセスでだけ更新（書き込みを減らすため） |
| 有効期限 | expiresAt | N | ○ | TTL 属性（UNIX 秒）。最終アクセス＋30 分 |

カート

| 論理名 | 属性名 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| 明細 | items | L | ○ | `{ productCode, quantity, addedAt }` の配列 |
| 版 | version | N | ○ | 条件付き更新（`version = :v`）で楽観ロック |
| 更新日時 | updatedAt | S | ○ | |
| 有効期限 | expiresAt | N | ○ | TTL 属性。会員：最終更新＋90 日、匿名：＋7 日 |

単価・商品名はカートに持たない（表示時に商品マスタから取る。価格が変わっても古い値を見せないため）。

## TTL

- `expiresAt` を TTL 属性に設定する。DynamoDB の TTL 削除は期限から最大 48 時間ほど遅れるため、**読み取り時に expiresAt を過ぎていれば無いものとして扱う**。
- 期限切れの削除で他のデータを消す処理はない（DynamoDB Streams は使わない）。

## 件数見込み

| 初期 | 月次増分 | 累積（保持期間内） |
|---|---|---|
| 0 件 | （TTL で消えるため増え続けない） | セッション：同時 約 5 万件、カート：約 80 万件（会員 90 日分） |

容量は約 2GB。オンデマンドで、ピーク時の読み取りは A1 が大半を占める。

## 保持・削除

- 保持は TTL のみ（上記）。バックアップはポイントインタイムリカバリを無効にする（消えても再ログイン・カートの入れ直しで済むと業務で合意済み）。
- 退会時は会員カートとセッションを即時に削除する（A8 と同じ手順）。
