# OBJ-030101：拠点進捗ダッシュボード

> 例：ダッシュボードの書き方。集計の定義、自動更新の間隔、ドリルダウンの遷移、ロールによるデータ範囲を本文に書く。集計そのものは API が行い、画面は表示の規則だけを持つ（題材：拠点進捗ダッシュボード）

## 概要

管理者が、拠点ごとの当月の点検完了率を一覧とグラフで確認し、遅れている拠点を見つけて詳細（未点検の設備）へたどる。

## レイアウト

`design/layout/progress-dashboard.png`

- 上段：サマリーカード 3 枚（全体完了率、未点検設備数、異常あり件数）
- 中段：拠点別完了率の横棒グラフ（完了率の昇順）
- 下段：拠点別の一覧表

## 状態表示

| 状態値 | 判定 | 表示 |
|---|---|---|
| done | 完了率 100% | 完了（緑） |
| ontrack | 完了率 ≧ 当月の経過日数の割合 | 順調（表示色なし） |
| behind | 完了率 ＜ 当月の経過日数の割合 | 遅れ（黄） |
| critical | 完了率 ＜ 50% かつ月の残り 7 日以内 | 要対応（赤） |
| none | total = 0 | 対象なし（グレー） |

過去月を表示しているときは、月末時点として判定する。

## 操作・イベント

| 契機 | 処理 |
|---|---|
| 初期表示 | 当月で拠点進捗取得API を呼ぶ |
| 対象月の変更 | 拠点進捗取得API を呼ぶ。過去月なら自動更新を止めてトグルを無効にする |
| 自動更新 | 5 分ごとに拠点進捗取得API を呼ぶ。タブが非表示の間は止め、表示に戻ったら直ちに 1 回呼ぶ |
| 手動更新ボタン | 直ちに呼ぶ。直前の呼び出しから 30 秒以内は無効 |
| 一覧の列見出し | 拠点名・完了率・異常ありで並び替え（画面内で行う）。既定は完了率の昇順 |
| グラフの棒・拠点名のクリック | 拠点詳細画面へ（拠点 ID と対象月を渡す） |
| 異常あり件数カードのクリック | 拠点詳細画面へ（異常ありで絞り込んだ状態）。拠点が 1 つだけなら直接、複数なら一覧を異常ありの拠点に絞る |

集計は API 側で 5 分ごとに作り直している（契約 CTR-F-004 の aggregatedAt）。画面の更新間隔はこれより短くしない。

## 入力チェック

なし（対象月は選択式で、範囲外は選べない）

## メッセージ

| ID | 種別 | 条件 | 文言 |
|---|---|---|---|
| E-3101 | エラー | 拠点進捗取得API のエラー | 進捗を取得できませんでした。［再読込］ |
| W-3101 | 警告 | 自動更新が 3 回続けて失敗 | 自動更新を停止しました。表示は {最終更新} 時点のものです。 |
| I-3101 | 情報 | 表示できる拠点が 0 | 表示できる拠点がありません。 |

自動更新の失敗では E-3101 を出さず、表示を残したまま次の更新を待つ（3 回で W-3101）。

## 権限

| ロール | データ範囲 |
|---|---|
| 本社管理者 | 全拠点 |
| 拠点管理者 | 担当する拠点のみ（サマリーカードも担当拠点だけで集計） |
| 点検者 | この画面は使えない（メニューに出さない） |

データ範囲の絞り込みは拠点進捗取得API が行う。
