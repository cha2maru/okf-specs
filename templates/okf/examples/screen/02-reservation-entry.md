# OBJ-210102：予約登録画面

> 例：入力・登録画面の書き方。入力チェック、確認ダイアログ、二重送信防止、メッセージを本文に書く。型・桁の正は契約（OpenAPI）で、画面固有のチェックと文言だけを書く（題材：予約登録画面）

## 概要

会員が、空き枠検索画面で選んだ店舗・日時の枠に対して、人数・メニュー・連絡事項を入力して予約を確定する。

## レイアウト

`design/layout/reservation-entry.png`（PC は 2 カラム：左に枠の情報、右に入力欄。スマホは 1 カラム）

|---|---|---|---|---|---|---|---|
| 店舗名 | 表示 | 出力 | | | | 遷移元から受け取った枠 | |
| 日時 | 表示 | 出力 | | yyyy/MM/dd(曜) HH:mm〜HH:mm | | 同上 | |

## 操作・イベント

| 契機 | 処理 |
|---|---|
| 初期表示 | 遷移元から受け取った枠 ID で空き枠照会API を呼び、残席数を取得して人数の上限を決める。残席 0 なら E-2105 を出して空き枠検索画面へ戻る |
| 項目からフォーカスが外れたとき | その項目の入力チェックを行い、エラーは項目の下に表示する |
| 予約する | 全項目の入力チェック。エラーがあれば先頭のエラー項目へスクロールして止める。なければ確認ダイアログ（店舗・日時・人数・メニュー・連絡事項）を表示する |
| 確認ダイアログの「確定」 | ボタンを無効にしてスピナーを出し、予約登録API を呼ぶ。リクエストには画面表示時に発行した冪等キー（UUID）を付ける。成功したら予約完了画面へ |
| 確認ダイアログの「修正する」 | ダイアログを閉じて入力に戻る（入力内容は保持） |
| 戻る | 入力がある場合は I-2102 で確認してから空き枠検索画面へ |
| ブラウザの再読込・離脱 | 入力がある場合はブラウザ標準の離脱確認を出す |

### 二重送信防止

- 「確定」は押した時点で無効にし、応答が返るまで再度押せない。
- 応答が返らずに再送しても、同じ冪等キーなので予約は 1 件しかできない（API 側の取り決めは契約 CTR-F-201）。
- 予約完了画面で戻るボタンを押した場合は、この画面ではなく空き枠検索画面へ戻す（履歴を置き換える）。

### API エラー時

| 応答 | 対応 |
|---|---|
| 409（枠が埋まった） | E-2105 を表示し、OK で空き枠検索画面へ |
| 409（同じ時間帯に予約あり） | E-2106 を表示し、入力に戻る |
| 422（入力エラー） | details の項目ごとに項目の下へ表示 |
| その他・通信エラー | 共通メッセージ。入力内容は保持し、「確定」を再度押せるようにする（冪等キーは変えない） |

| 遷移元・契機 | 条件 | 遷移先 |
|---|---|---|

## 入力チェック

| 項目 | チェック | メッセージ ID |
|---|---|---|
| 人数 | 必須 | E-2101 |
| メニュー | 必須 | E-2101 |
| 連絡事項 | 200 文字以内、絵文字不可 | E-2102 |
| 連絡先電話番号 | 必須、形式 | E-2101、E-2103 |
| 日時 | 現在時刻から 1 時間以上先（表示中に過ぎた場合） | E-2104 |

## メッセージ

| ID | 種別 | 条件 | 文言 |
|---|---|---|---|
| E-2101 | エラー | 必須項目が未入力 | {項目名}を入力してください。 |
| E-2102 | エラー | 連絡事項が不正 | 連絡事項は 200 文字以内で、絵文字を使わずに入力してください。 |
| E-2103 | エラー | 電話番号の形式誤り | 電話番号は数字とハイフンで入力してください。 |
| E-2104 | エラー | 受付締切を過ぎた | この枠の受付は締め切りました。別の枠を選んでください。 |
| E-2105 | エラー | 枠が埋まった | 申し訳ありません。この枠は満席になりました。 |
| E-2106 | エラー | 同じ時間帯に予約がある | 同じ時間帯にすでに予約があります。 |
| I-2101 | 確認 | 確認ダイアログ | 以下の内容で予約します。よろしいですか。 |
| I-2102 | 確認 | 入力中に戻る | 入力内容は保存されません。戻りますか。 |

## 権限

ログイン中の会員のみ。自分の予約だけを登録できる（会員 ID はトークンから決まり、画面からは送らない）。
