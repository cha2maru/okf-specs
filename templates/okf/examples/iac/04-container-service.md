# OBJ-020401：注文APIサービス定義

## 概要

注文管理アプリ（SYS-01）の注文 API を動かすコンテナサービス。公開ロードバランサー（OBJ-020101）のターゲットグループ `chumon-api-tg` に登録され、負荷に応じてタスク数を増減する。

動かすアプリ：

| 開発オブジェクト | 所属 | 備考 |
|---|---|---|
| OBJ-010201 注文登録API | SYS-01 / CMP-0102 注文API | `POST /orders` |
| OBJ-010202 注文照会API | SYS-01 / CMP-0102 | `GET /orders/{orderId}` |
| OBJ-010203 注文取消API | SYS-01 / CMP-0102 | `DELETE /orders/{orderId}` |

3 つは同じイメージ（`chumon-api`）に入り、1 つのサービスで動く。注文確定イベントの購読側（在庫引当処理）は別サービス OBJ-020405 で動かす。

関連するリソース：

| リソース | 開発オブジェクト |
|---|---|
| イメージの置き場（レジストリ） | OBJ-020402 注文APIリポジトリ定義 |
| タスクロール・実行ロール | OBJ-020403 注文APIロール定義 |
| ログの出力先 | OBJ-020404 注文APIロググループ定義 |
| セキュリティグループ | OBJ-020406 注文APIのSG定義 |

## 設定値

| 項目 | 値 | 根拠（要件・非機能契約） |
|---|---|---|
| イメージ | OBJ-020402 の `chumon-api`、タグはコミットハッシュ（`latest` は使わない、タグの上書き禁止） | SYS-02 共通方針 |
| タスクのサイズ | 1 vCPU・2 GB メモリ | CTR-N-031 注文API応答性能（負荷試験 LT-05 の結果） |
| コンテナのポート | 8080 | OBJ-020101 のターゲットグループ |
| 配置 | 非公開サブネット 2 つ（AZ-a、AZ-c）に分散 | CTR-N-032 注文可用性 |
| 停止時の猶予 | 30 秒（SIGTERM 後、処理中の要求を終えてから停止） | CTR-N-032 |
| デプロイ | ローリング（最小 100%、最大 200%）、失敗時は自動で前の版に戻す | CTR-N-032 |

### アプリに渡す値

値そのものは各契約の提供側が管理する。ここでは渡し方だけを定める。

| 環境変数 | 渡し方 | 取り決め |
|---|---|---|
| `CHUMON_DB_HOST`、`CHUMON_DB_PORT`、`CHUMON_DB_NAME` | 平文の環境変数 | CTR-F-022 注文DB接続 |
| `CHUMON_DB_SECRET` | シークレットから起動時に注入 | CTR-F-022 |
| `ORDER_EVENT_TOPIC` | 平文の環境変数 | CTR-F-002 注文確定イベント |
| `APP_ENV` | 平文（`prod`／`stg`） | SYS-01 共通方針 |

### オートスケール

| 項目 | 値 | 根拠 |
|---|---|---|
| 最小・既定・最大のタスク数 | 2・2・12 | CTR-N-032（AZ ごとに 1 以上）、CTR-N-031（ピーク 300 件/秒） |
| 指標 1 | CPU 使用率の平均 60% を保つ | CTR-N-031 |
| 指標 2 | タスクあたりのリクエスト数 毎分 1,500 を保つ | CTR-N-031 |
| スケールアウト | 待ち 60 秒 | ― |
| スケールイン | 待ち 300 秒（増減の繰り返しを防ぐ） | ― |
| 予定スケール | セール日（運用カレンダー）は 9:00〜21:00 の最小を 6 | RUL-021 |

### ヘルスチェック

| 種類 | 対象 | 値 |
|---|---|---|
| ロードバランサー | `GET /healthz` が 200 | 間隔 15 秒、タイムアウト 5 秒、正常 2 回・異常 3 回で判定 |
| コンテナ | `curl -f localhost:8080/healthz` | 間隔 30 秒、異常 3 回で置き換え |
| 起動直後の猶予 | ― | 60 秒（この間の失敗は数えない） |

`/healthz` はプロセスの生存だけを返し、DB への接続は確かめない（DB 障害で全タスクを置き換えないため）。DB を含む確認は `/readyz` として監視（下表）で使う。

## 冗長化・配置

2 つの AZ にタスクを均等に置く。片方の AZ が止まると、残りの AZ でタスクを補い、最小 2 を保つ。

## セキュリティ

- 受け付けるのは OBJ-020101 の SG からの 8080 だけ（OBJ-020406）。
- 外向きは注文 DB（5432）、イベント基盤、レジストリ、ログサービスのエンドポイントのみ。インターネットへは出ない。
- タスクロール（OBJ-020403）の権限は、CTR-F-022 のシークレットの読み取りと、CTR-F-002 のトピックへの発行に限る。
- コンテナは読み取り専用のルートファイルシステム、root 以外のユーザーで動かす。

## バックアップ・保持

なし（状態を持たない）。ログの保持は OBJ-020404（90 日）。

## 監視

| 監視項目 | 閾値 | 通知先 |
|---|---|---|
| 実行中のタスク数 | 2 未満が 3 分継続 | 当番（電話） |
| タスクの異常終了 | 10 分で 3 回超 | 運用チャネル |
| CPU 使用率 | 最大タスク数で 15 分平均 80% 超 | 運用チャネル（上限の見直し） |
| `/readyz` の失敗 | 3 分継続 | 運用チャネル |
| デプロイの自動ロールバック | 1 回 | 注文アプリ担当 |

## 出力

他システムへ提供する値はない。
