# OBJ-310103：予約一覧取得API

> 例：検索 API の絞り込み・並び順・ページング・権限によるデータ範囲を、共通方針との差分として書く（題材：予約システムの予約一覧取得API）

<!-- クエリパラメータと応答の型は CTR-F-302（予約API、提供：CMP-3101）に書く。
     ページングの共通仕様（オフセット方式、limit の既定 20・上限 100）は SYS-31 の共通方針に書いてある。ここには違う点だけを書く。 -->

## 概要

条件に合う予約の一覧を、利用日時の順に返す。利用者は自分の予約、施設スタッフは担当施設の予約、管理者はすべての予約を見る。

## 認証・認可

| ロール | 見られる範囲 | 備考 |
|---|---|---|
| 利用者 | 自分の予約だけ | `userId` を指定したら無視せず 403（他人の ID を試す操作を記録するため） |
| 施設スタッフ | 担当施設（施設担当テーブル OBJ-310404）の予約 | 担当外の `facilityId` を指定したら 403 |
| 管理者 | すべて | ― |

- データ範囲の条件は、利用者が指定した絞り込みと AND で必ず付ける。範囲の条件を付け忘れないよう、検索の組み立てはロールから範囲条件を作る部分を先に通す。
- 施設スタッフに返す予約者の電話番号は下 4 桁以外を伏せる。管理者には全桁を返す。

## 入力の業務制約

- 利用日の範囲（`from`・`to`）は必須。期間は 92 日以内。`from` は過去 2 年より前を指定できない（それより古い予約は別の保管先）。
- `status` は複数指定可（OR）。省略時は「取消」以外。
- `keyword` は予約者氏名（かな）の前方一致。2 文字以上。施設スタッフと管理者だけが使える（利用者が指定したら 400）。
- `sort` は `startAt`（既定）、`createdAt` のどちらか。昇順・降順を選べる。それ以外の項目は 400。

## 処理

1. ロールと担当施設から、データ範囲の条件を作る。
2. 入力の絞り込み条件を加える。
3. 並び順に、同じ値のときの順序を決めるため予約 ID を必ず加える（例：`startAt, id`）。
4. カーソルがあれば、カーソルの（並び順の値, 予約 ID）より後ろの行から `limit＋1` 件読む。
5. `limit＋1` 件目があれば、`limit` 件目からカーソルを作って `nextCursor` に入れる。
6. 予約に施設名・予約者名を付けて返す（施設テーブル・利用者テーブルを結合）。

## 出力

- 予約の配列と `nextCursor`（最後のページでは null）。
- 総件数は返さない（期間が長いと数えるのが重いため）。画面は「さらに読み込む」で次のページを取る。

## ページング（共通方針との差分）

| 項目 | 共通方針 | この API |
|---|---|---|
| 方式 | オフセット（`page`） | カーソル（`cursor`）。一覧を見ている間に予約が増えても、行の飛びや重複が起きないようにするため |
| `limit` | 既定 20、上限 100 | 既定 50、上限 200（スタッフが 1 日分を 1 画面で見るため） |
| カーソルの中身 | ― | （並び順の値, 予約 ID, 絞り込み条件のハッシュ）を署名して Base64 にしたもの。条件を変えて使い回したら 400 |

## エラー

| 条件 | ステータス | メッセージ ID | 文言 |
|---|---|---|---|
| 日付の範囲がない・92 日を超える | 400 | E-3101 | 期間は 92 日以内で指定してください |
| 担当外の施設・他人の予約を指定 | 403 | E-3102 | この予約を表示する権限がありません |
| カーソルが不正・条件と合わない | 400 | E-3103 | 一覧を最初から読み込み直してください |
| 利用者が `keyword` を指定 | 400 | E-3104 | （画面には出さない） |
| DB タイムアウト（5 秒） | 503 | 共通 | 共通方針どおり |

## 排他・トランザクション・冪等性

参照だけなのでロックは取らない。読み取りは読み取り専用レプリカに向ける（DB 接続 CTR-F-307 の読み取り用の接続先）。レプリカの遅れ（最大数秒）で、登録直後の予約が出ないことがある。登録直後の画面は、登録 API の応答を表示に使う。

## ログ

- 共通方針どおり。加えて、403 は利用者 ID・指定した施設 ID・userId を WARN で出す（不正な参照の検知）。
- `keyword` の値はログに出さない（氏名のため）。
