# OBJ-210103：決済与信API

> 例：外部 API を呼ぶ API で、タイムアウト・429・5xx・サーキットブレーカーと「結果不明」の扱いを書く（題材：EC の決済与信API）

<!-- 決済代行サービスの API・エラーコードの意味・送信上限は CTR-F-206（外部API仕様）に書く。
     ここには、この API が先方の応答をどう扱うか（回数・時間・状態）だけを書く。 -->

## 概要

受付済みの注文について、決済代行サービスにカードの与信（オーソリ）を依頼し、結果を注文に反映する。カード番号は端末から決済代行サービスへ直接送られ、この API はトークンだけを受け取る。

## 認証・認可

共通方針どおり（会員のアクセストークン）。注文の会員 ID がトークンの会員 ID と一致すること。

## 入力の業務制約

- 注文の状態が「受付」または「与信拒否」であること（与信拒否のあと別のカードでやり直せる）。
- 注文に「要求中」または「与信済」の与信がないこと（一意制約：注文 ID ＋ 有効な与信）。
- 与信額は注文の合計金額を使う。リクエストに金額は持たせない。

## 処理

DB のトランザクションを開いたまま外部を呼ばない。外部呼び出しの前後でトランザクションを分ける。

1. （トランザクション 1）与信テーブル（OBJ-210406）に状態＝要求中で 1 行登録し、注文を「与信処理中」にしてコミットする。与信 ID を先方への冪等キーにする。
2. サーキットブレーカーが開いていれば、先方を呼ばずに手順 4 の「利用不可」へ進む。
3. 決済代行サービスの与信 API を呼ぶ（Idempotency-Key＝与信 ID）。再試行は下の表のとおり。
4. （トランザクション 2）結果に応じて更新し、応答を返す。

| 先方の結果 | 与信 | 注文 | この API の応答 |
|---|---|---|---|
| 承認 | 与信済（先方の取引 ID を保存） | 与信済 | 201 |
| 拒否（カード側の理由） | 与信拒否（先方の拒否コードを保存） | 与信拒否 | 422 E-2111 |
| 利用不可（ブレーカー開・429 の上限超え） | 中止 | 受付に戻す | 503 E-2112 |
| 結果不明（再試行してもタイムアウト・5xx） | 結果不明 | 与信処理中のまま | 202 I-2113 |

- 「結果不明」の与信は、与信照会処理（OBJ-210305）が先方に冪等キーで問い合わせて確定させる。画面は注文詳細を数秒おきに読み直して結果を表示する。

## 外部呼び出し

| 項目 | 値 | 理由 |
|---|---|---|
| 接続タイムアウト | 2 秒 | |
| 応答タイムアウト | 10 秒 | 先方の与信 API の p99 が 4 秒（CTR-F-206） |
| 全体の時間予算 | 15 秒 | 画面のタイムアウト 20 秒より短くする。予算を使い切ったら再試行しない |

| 対象とする失敗 | 再試行 | 間隔 | 備考 |
|---|---|---|---|
| 接続タイムアウト・接続拒否 | 2 回 | 0.5 秒、1 秒 | 先方に届いていないので安全 |
| 応答タイムアウト・5xx | 2 回 | 0.5 秒、1 秒 | 同じ冪等キーで送るため、先方で二重の与信にならない |
| 429 | Retry-After が 2 秒以下なら 1 回 | Retry-After | 2 秒を超えたら「利用不可」 |
| 400・401・403 | しない | ― | こちらの不具合か設定の誤り。500 を返しアラート |
| 402（拒否） | しない | ― | 業務上の結果として扱う |

## サーキットブレーカー

- 単位：決済代行サービス全体で 1 つ（API コンテナごとに持つ）。
- 開く条件：直近 30 秒で 20 回以上呼び、応答タイムアウト・5xx・接続失敗が 50% 以上。429 と 4xx は数えない。
- 開いている時間：30 秒。その後半開きにして 3 回だけ通し、すべて成功したら閉じる。1 回でも失敗したらまた 30 秒開く。
- 開いている間は E-2112 を返す。開いた・閉じたときにログを出し、5 分以上開いたままならアラート。

## エラー

| 条件 | ステータス | メッセージ ID | 文言 |
|---|---|---|---|
| 注文がない・他人の注文 | 404 | E-2110 | 注文が見つかりません |
| 注文の状態が与信できない・与信中 | 409 | E-2114 | この注文はお支払い手続き中です |
| カードが拒否された | 422 | E-2111 | カードがご利用いただけませんでした。別のカードをお試しください |
| 決済サービスが利用不可 | 503 | E-2112 | 現在カード決済をご利用いただけません。しばらくしてからお試しください |
| 結果不明 | 202 | I-2113 | お支払いを確認しています |
| 先方が 400・401・403 | 500 | 共通 | 共通方針どおり |

## 排他・トランザクション・冪等性

- 同じ注文への同時の要求は、与信テーブルの一意制約で片方だけが通る（もう片方は 409）。
- この API 自体はクライアントの冪等キーを取らない。再送は「与信中」の 409 か、前回の結果に応じた応答になる。
- 先方に対しては与信 ID で冪等にするため、再試行・照会・再起動のどこで切れても二重の与信は起きない。

## ログ

- カードのトークン・先方の拒否コードの詳細はログに出さない（拒否コードは与信テーブルにだけ残す）。
- 先方への呼び出しごとに、与信 ID・先方のリクエスト ID・ステータス・所要時間・試行回数を INFO で出す。
