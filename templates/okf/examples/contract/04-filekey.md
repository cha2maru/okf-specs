# CTR-F-031：帳票ファイル置き場

<!-- 提供側は帳票ファイル群（CMP-0105）。置き場の物理は CTR-F-032 帳票バケット接続（実体は OBJ-020301）。
     帳票を作る側と読む側が別システムのため厚い契約にする。 -->

## 当事者

| 役割 | コンポーネント | 開発オブジェクト |
|---|---|---|
| 提供 | CMP-0105 帳票ファイル（SYS-01 販売管理アプリ） | OBJ-010501 請求書PDF、OBJ-010502 納品書PDF、OBJ-010503 帳票生成一時ファイル |
| 書き込み | CMP-0104 帳票発行（SYS-01） | OBJ-010401 月次請求書発行バッチ、OBJ-010402 納品書発行処理 |
| 読み取り | CMP-0701 会員ポータル（SYS-07） | OBJ-070201 帳票ダウンロードAPI |

## キー形式

| ファイル | キー |
|---|---|
| 請求書PDF | `reports/invoice/{yyyy}/{MM}/{customerId}/{docNo}.pdf` |
| 納品書PDF | `reports/delivery/{yyyy}/{MM}/{customerId}/{docNo}.pdf` |
| 帳票生成一時ファイル | `tmp/{jobId}/{seq}.pdf` |

| 変数 | 範囲 | 例 |
|---|---|---|
| `yyyy`、`MM` | 帳票の**発行日**（JST）の年・月。2 桁ゼロ埋め | `2026`、`10` |
| `customerId` | `C` ＋ 8 桁 | `C00012345` |
| `docNo` | 請求書は `INV-` ＋ 10 桁、納品書は `DLV-` ＋ 10 桁。再発行は末尾に `-r{n}`（n は 1〜9） | `INV-0000123456-r1` |
| `jobId` | UUID | |
| `seq` | 1〜999 | |

- キーの最大長は 200 文字。英数字・`-`・`/`・`.` 以外は使わない。
- 一覧の取得は `reports/{種別}/{yyyy}/{MM}/{customerId}/` 単位で行う（バケット全体を一覧しない）。

## ファイル形式・上限

| 項目 | 取り決め |
|---|---|
| 形式 | PDF/A-2b（長期保存のため）。フォントは埋め込む |
| Content-Type | `application/pdf` |
| 1 ファイルの上限 | 10 MB（明細 1,000 行の請求書で約 2 MB） |
| メタデータ | `doc-type`（invoice／delivery）、`issued-at`（ISO 8601、`+09:00`）、`sha256`（本文のハッシュ）、`reissue-of`（再発行のとき元の docNo） |
| 暗号化 | 置き場側で行う（CTR-F-032）。書き込み側は暗号化しない |

## 上書き・削除の規約

- `reports/` 配下は**上書き禁止**。同じキーへの書き込みは条件付き書き込み（存在しないときだけ）で行い、既にあれば失敗として扱う。
- 内容を直すときは再発行とし、新しい `docNo`（`-r{n}`）で書く。元のファイルは残す。どちらが最新かは販売管理アプリの帳票テーブル（CTR-F-030 販売DB の「帳票」）で判断する。
- `reports/` 配下は利用側から削除しない。7 年経過後に置き場側のライフサイクルで消える。
- `tmp/` 配下は書き込み側が処理の終わりに消す。消し忘れは 1 日で自動削除される（置き場側）。
- 読み取り側は `sha256` メタデータで改ざんの有無を確かめてから利用者へ渡す。
