# CTR-F-021：在庫DB接続

<!-- 提供側はデータ基盤（CMP-0202）。物理の構成（台数・AZ）は OBJ-020201 に書き、ここには書かない。
     論理（ER 図）は CTR-F-020 在庫DB。 -->

## 当事者

| 役割 | コンポーネント |
|---|---|
| 提供 | CMP-0202 データ基盤（SYS-02 クラウド基盤）。実体は OBJ-020201 在庫DBクラスタ |
| 利用 | CMP-0101 在庫照会、CMP-0102 入出庫（SYS-01 在庫管理アプリ） |

## 提供する値

| 名前 | 渡し方 | 値の生成元 | 説明 |
|---|---|---|---|
| `ZAIKO_DB_HOST` | 環境変数（実行環境 OBJ-020401 が注入） | OBJ-020201 のクラスタエンドポイント | 書き込み用。フェイルオーバーで指す先が変わる（名前は変わらない） |
| `ZAIKO_DB_READER_HOST` | 環境変数 | OBJ-020201 のリーダーエンドポイント | 参照専用。遅延あり（下記） |
| `ZAIKO_DB_PORT` | 環境変数 | 固定値 | `5432` |
| `ZAIKO_DB_NAME` | 環境変数 | 固定値 | `zaiko` |
| `ZAIKO_DB_SECRET` | 環境変数に**シークレットの ID** を入れる。中身はアプリが起動時に取得 | OBJ-020204 在庫DBシークレット | 下記の構造 |

- 値は環境ごとに異なる。名前は全環境で同じ。
- 接続文字列を組み立てるのはアプリ側。ホスト名を設定ファイルに直書きしない。

## シークレットの構造

```json
{
  "username": "zaiko_app",
  "password": "（自動生成、32 文字）",
  "engine": "postgres",
  "host": "（ZAIKO_DB_HOST と同じ値）",
  "port": 5432,
  "dbname": "zaiko"
}
```

- ローテーション：30 日ごと、2 ユーザー交互方式（`zaiko_app` と `zaiko_app_clone`）。切り替え中も古いパスワードは次のローテーションまで有効。
- アプリはシークレットを最大 1 時間キャッシュしてよい。認証エラー（SQLSTATE `28P01`）を受けたら、キャッシュを捨てて取り直し、1 回だけ再接続する。

## 通信・権限

| 項目 | 取り決め |
|---|---|
| TLS | 必須（`sslmode=verify-full`）。CA 証明書はコンテナイメージに同梱（SYS-02 共通方針の CA バンドル） |
| 接続元 | 実行環境の SG（OBJ-020406）からのみ |
| 接続数の上限 | タスクあたり書き込み 10・参照 10（プール）。全体の上限は 400、アプリの合計で 300 まで（残りは運用・移行用） |
| 文のタイムアウト | 30 秒（DB 側で強制）。長い集計はバッチ用の別ユーザーを使う（この契約の範囲外） |
| 付与する権限 | スキーマ `zaiko` のテーブルに SELECT・INSERT・UPDATE・DELETE。DDL は不可 |
| スキーマの変更 | マイグレーション用ユーザー（CI からのみ）が行う。この契約では提供しない |

## 障害時に利用側がすべきこと

| 事象 | 利用側の振る舞い |
|---|---|
| ライターのフェイルオーバー（60 秒以内） | 接続エラーを受けたらプール内の接続をすべて捨てる。DNS のキャッシュは 5 秒以下にする。指数バックオフ（1, 2, 4, 8 秒…最大 60 秒）で再接続 |
| フェイルオーバー中の書き込み | 処理中のトランザクションは失敗する。冪等な処理だけ自動で再実行し、それ以外は呼び出し元へ 503 を返す |
| 読み取り専用エラー（SQLSTATE `25006`） | 旧ライターにつながっている。接続を捨てて再接続 |
| リーダーの遅延 | 通常 100 ミリ秒以内、最大 5 秒を許容する。書いた直後に読む処理（入出庫の確認画面）はライターから読む |
| リーダーの停止 | `ZAIKO_DB_HOST` へ切り替えて読む（性能低下は許容） |
| 計画メンテナンス（日曜 03:30〜04:30） | 最大 5 分の切断がある。夜間バッチはこの時間帯に動かさない |
