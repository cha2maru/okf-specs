# CTR-F-041：メール配信サービス

<!-- 先方の仕様を写さない。先方の版が変わったら resource_version を上げ、差分を確かめる。 -->

## 利用範囲

| 先方の API | 用途 | 利用する開発オブジェクト |
|---|---|---|
| `POST /v3/mail/send` | 予約確定・取消・前日リマインドのメール送信 | OBJ-010401 予約通知処理、OBJ-010402 リマインド送信バッチ |
| `GET /v3/suppressions/bounces` | 不達アドレスの取得（日次） | OBJ-010403 不達アドレス取込バッチ |

`POST /v3/mail/send` の項目の対応：

| 先方の項目 | こちらの項目 | 備考 |
|---|---|---|
| `from.email` | 固定値 `no-reply@yoyaku.example.jp` | 送信ドメインは先方で認証済み（SPF・DKIM） |
| `from.name` | 固定値「〇〇レストラン予約」 | |
| `personalizations[0].to[0].email` | 会員.メールアドレス（CTR-F-010 予約DB） | 1 通に宛先 1 件。一斉送信はしない |
| `template_id` | 通知種別ごとの先方テンプレート ID（下表） | 文面は先方の管理画面で管理 |
| `personalizations[0].dynamic_template_data` | 予約.店舗名、予約.来店日時、予約.人数、予約.予約番号 | 日時は `2026年10月3日（土）18:30` の形に整えて渡す |
| `custom_args.reservationId` | 予約.予約番号 | 不達の追跡用 |
| `headers.X-Idempotency-Key` | 通知ID（UUID） | 先方は 24 時間重複を除く |
| 応答 `x-message-id` | 通知履歴.先方メッセージID | 問い合わせ用に保存 |

| 通知種別 | 先方テンプレート ID |
|---|---|
| 予約確定 | `d-7a1f…01` |
| 予約取消 | `d-7a1f…02` |
| 前日リマインド | `d-7a1f…03` |

`GET /v3/suppressions/bounces` は `start_time`（前回取得時刻）を渡し、応答の `email` を会員.メール不達フラグに反映する。

## 認証

- API キーを `Authorization: Bearer` で送る。
- キーはシークレット `yoyaku/prod/mail-api-key`（OBJ-020205）に保管し、送信権限と不達参照権限だけを持つキーを使う。
- キーの更新は年 1 回、先方管理画面で新キーを発行 → シークレットを更新 → 旧キーを無効化。

## エラー時の扱い

| 事象 | 対応 |
|---|---|
| 400（項目の誤り） | 再試行しない。通知履歴を「失敗」にし、エラーログに先方の `errors[].message` を残す |
| 401・403 | 再試行しない。キーの失効とみなし、運用担当へ即時通知（全件が失敗するため） |
| 413（本文が大きすぎる） | 再試行しない。起きないはず（本文はテンプレート）なので不具合として扱う |
| 429 | `Retry-After` の秒数だけ待って再試行。ヘッダーがなければ 60 秒。最大 5 回 |
| 5xx・タイムアウト（接続 3 秒・応答 10 秒） | 指数バックオフ（10, 30, 90 秒）で 3 回再試行。尽きたら通知用 DLQ（OBJ-020506）へ。DLQ は 1 時間ごとに再投入を 6 回まで |
| 202 だが不達 | 送信 API では分からない。日次の不達取込で会員に印を付け、次回から送らない |

再試行は同じ `X-Idempotency-Key` で行う（二重送信を防ぐ）。

## 上限・SLA

| 項目 | 内容 |
|---|---|
| 契約プラン | Pro（月 10 万通まで。超過分は従量） |
| 先方の流量制限 | 毎秒 100 リクエスト |
| こちらの想定送信量 | 平常 1 日 3,000 通、ピーク（年末）1 日 12,000 通。前日リマインドは 18:00 に最大 2,000 通を 20 分で送る（毎秒 2 通） |
| 先方の SLA | 月間稼働率 99.95%（API 受付）。配信の所要時間は保証なし |
| こちらの前提 | 確定メールは受付から 5 分以内に届くこと（CTR-N-002）。先方が止まった場合の代替手段は持たず、画面の予約確認で代替する（RUL-015） |
| 窓口 | 先方サポート（管理画面のチケット）。障害情報は先方ステータスページを監視 |
