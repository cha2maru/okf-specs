# OBJ-310301：予約確定メール送信処理

> 例：非同期処理の再試行・冪等性・DLQ を表で決め、メッセージ契約に書いたことは重ねない（題材：予約システムの予約確定メール送信）

<!-- 受信するメッセージ（予約確定イベント）の項目と配送保証は CTR-F-304（提供：CMP-3103）に書く。
     外部メール配信サービスのエラーの意味は CTR-F-305 に書く。ここにはこの処理での扱いだけを書く。 -->

## 概要

予約が確定したときに、予約者へ確定メールを 1 通送る。送信の結果を送信履歴テーブルに残す。

## 起動契機

- キュー `reservation-confirmed`（CTR-F-306 メッセージ基盤の接続情報で取得）をロングポーリングで受信する。
- 配送は at-least-once（CTR-F-304）。同じメッセージが 2 回以上届く前提で作る。
- 発行側（予約登録API OBJ-310101）はアウトボックス方式で発行するため、受信した時点で予約はコミット済みである。

## 入力

使う項目は `eventId`、`reservationId`、`schemaVersion` だけ。メール本文に載せる値は、受信時点の予約テーブルから読み直す（イベントの値は古い可能性があるため）。

## 処理

1. `schemaVersion` が 2 以外なら、処理せず DLQ へ送る（未対応の版）。
2. 送信履歴テーブル（OBJ-310405）を（reservationId, 通知種別＝予約確定）で検索する。
   - 状態＝送信済：何もせずメッセージを削除する（重複受信）。
   - 状態＝送信中で更新から 10 分未満：可視性タイムアウトの延長だけして終了する（他のワーカーが処理中）。
   - それ以外：状態＝送信中で登録（または更新）する。
3. 予約テーブル（OBJ-310401）を読む。状態が「確定」でなければ（確定後すぐ取り消された等）、送信履歴を「対象外」にして終了する。
4. 利用者テーブル（OBJ-310403）からメールアドレスと言語を、施設テーブル（OBJ-310402）から施設名・住所を読む。
5. 言語に合うテンプレートでメールを組み立てる（出力の節）。
6. メール配信サービス（CTR-F-305）の送信 API を呼ぶ。冪等キーに送信履歴 ID を渡す。
7. 送信履歴を状態＝送信済、先方のメッセージ ID を記録して更新し、キューのメッセージを削除する。

## 出力

| 項目 | 内容 |
|---|---|
| 差出人 | no-reply@yoyaku.example.jp（表示名：○○予約センター） |
| 件名 | 【予約確定】{施設名} {利用日 M月d日(曜)} {開始時刻} |
| 本文 | テンプレート `mail/reservation-confirmed.{ja,en}.txt`。予約番号、施設名・住所、利用日時、人数、取消期限、予約詳細画面の URL |
| 日時の表示 | 施設のタイムゾーンで表示する（共通方針は JST 固定。海外施設があるための差分） |

## 再試行

| 対象とする失敗 | 回数 | 間隔 | タイムアウト | 最終失敗時の行き先 |
|---|---|---|---|---|
| 送信 API の 5xx・タイムアウト | 5 | キューの再配送（30 秒、2 分、10 分、30 分、2 時間） | 接続 3 秒、応答 10 秒 | DLQ `reservation-confirmed-dlq` |
| 送信 API の 429 | 上と共通 | Retry-After があればそれを可視性タイムアウトにする | 同上 | 同上 |
| DB 接続不可 | 上と共通 | 上と同じ | ― | 同上 |
| 送信 API の 4xx（宛先不正など） | 0 | ― | ― | 送信履歴を「送信不可」にして削除（DLQ に入れない） |

- DLQ に入ったら監視でアラートを上げる。原因を直したら、運用手順「DLQ 再投入」で元のキューに戻す（処理は冪等なので戻してよい）。

## 冪等性・重複排除

- 重複のキーは `eventId` ではなく（reservationId, 通知種別）とする。発行側の再発行で `eventId` が変わっても 2 通送らないため。
- 送信 API には送信履歴 ID を冪等キーとして渡す。手順 6 が成功して手順 7 の前に落ちても、再実行で先方が二重送信しない。

## 多重度・順序

- ワーカーは最大 10 並列。順序の保証は不要（予約ごとに 1 通で、他の予約と関係しない）。
- メール配信サービスの送信上限（CTR-F-305：毎秒 50 通）を超えないよう、ワーカー全体で毎秒 40 通に制限する。

## エラー

| 条件 | 対応 |
|---|---|
| 予約が存在しない | 警告ログを出し、送信履歴を「対象外」にして削除（発行側の不具合の調査用にログへ eventId を出す） |
| メールアドレス未登録 | 送信履歴を「送信不可」にして削除（窓口が送信履歴を見て電話で連絡する運用） |
| テンプレートの差し込み失敗 | DLQ へ（再試行しても直らないため即時） |

## ログ・監視

- メールアドレスはログに出さない（利用者 ID だけ）。件名は出してよい。
- アラート：DLQ に 1 件以上、または受信から送信済までの遅延が 5 分を超えた件数が 10 分間で 20 件以上。
