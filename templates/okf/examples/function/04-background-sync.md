# OBJ-010301：同期処理

## 概要

端末内に保存した未送信の点検結果と写真を、利用者の操作なしにクラウドへ送る（SPC-003）。送信途中で圏外になっても、再度つながったときに重複なく送り終える。

## 起動契機

| 契機 | 内容 |
|---|---|
| 通信回復 | OS のネットワーク状態がオフライン → オンラインに変わったとき |
| 保存直後 | 点検入力画面（OBJ-010102）で保存したとき。オフラインなら何もしない |
| アプリ起動・前面復帰 | アプリの起動時と、バックグラウンドから前面に戻ったとき |
| 定期 | Android：WorkManager で 15 分ごと（ネットワーク接続を条件）。iOS：BGTaskScheduler に登録（実行時刻は OS 任せ） |
| 手動 | 点検一覧画面（OBJ-010101）の下に引く操作 |

どの契機でも同じ処理を呼ぶ。実行中に別の契機が来たら、実行中の処理が終わった後に 1 回だけ続けて実行する（多重度の節）。

## 入力

- ローカル点検テーブル（OBJ-010201）の sendState が「未送信」または「結果送信済」の行。保存日時の古い順。
- 想定件数：通常 1〜20 件。圏外の現場が続いた場合で最大 300 件、写真は 1 件あたり最大 10 枚。

## 処理

1. 対象の行を保存日時の古い順に 1 件ずつ取り出す（並列にしない）。
2. sendState を「送信中」にする。この間、点検入力画面はその行を編集できない。
3. sendState が「未送信」だった行は、POST /inspections（OBJ-020101）を呼ぶ。
   - Idempotency-Key に行の idempotencyKey（保存時に UUID で採番済み）を渡す。
   - 201・200 のどちらでも成功とし、応答の inspectionId を行に保存して sendState を「結果送信済」にする。
4. 写真を、sentPhotoCount＋1 枚目から順に PUT /inspections/{inspectionId}/photos/{n}（OBJ-020102）で送る。
   - n は撮影順の 1 始まり。1 枚送るごとに sentPhotoCount を更新する（途中で切れても続きから送れる）。
5. 全写真を送り終えたら sendState を「送信済」にし、lastError を消す。
6. 次の行へ進む。対象がなくなったら終了する。

## 出力・状態遷移

```
未送信 ──(送信開始)──→ 送信中 ──(POST 成功)──→ 結果送信済 ──(写真すべて成功)──→ 送信済
  ▲                      │                         │
  └──(通信断・5xx)────────┴──────(通信断・5xx)──────┘   ※結果送信済のまま残る場合あり
                         │
                         └──(回復不能なエラー)──→ 送信エラー ──(利用者が修正して保存)──→ 未送信
```

- 起動時に「送信中」の行が残っていたら（前回の強制終了）、inspectionId の有無で「未送信」か「結果送信済」に戻す。
- 一覧画面はローカル点検テーブルの変更を監視して表示を変える。同期処理から画面へ直接は知らせない。

## 再試行・冪等性

| 対象とするエラー | 回数 | 間隔 | 冪等にする方法 |
|---|---|---|---|
| 通信不可・タイムアウト（接続 10 秒、写真の送信 60 秒） | 1 回の実行中は 3 回 | 5 秒、15 秒、45 秒 | 結果は Idempotency-Key、写真は同じ n の上書き |
| 5xx・429 | 1 回の実行中は 3 回 | 429 は Retry-After、5xx は上と同じ | 同上 |
| 上の回数を超えた | 次の起動契機まで待つ | ― | 行は元の状態（未送信／結果送信済）に戻す |

- 1 回の実行で 3 回失敗したら、その実行は打ち切る（後ろの行も送らない。圏外の可能性が高いため）。

## 多重度・排他

- 同期処理は端末内で同時に 1 本だけ。実行中フラグはプロセス内に持つ（端末内の他プロセスからは呼ばれない）。
- 点検入力画面との競合は「送信中は編集不可」で避ける。送信エラーの行は利用者が編集でき、保存すると「未送信」に戻る。

## エラー

| 条件 | 回復 | 対応 |
|---|---|---|
| 通信不可・タイムアウト・5xx・429 | 可能 | 再試行の節のとおり。利用者には知らせない（一覧の「未送信」表示のまま） |
| 401（トークン切れ） | 可能 | トークンを更新して 1 回だけやり直す。更新もできなければ打ち切り、次回ログイン後に送る |
| 400（入力不正）・404（設備なし） | 不能 | 「送信エラー」にし、lastError に応答の code を保存。一覧に M01-201 を表示する |
| 写真の 400・413・415（枚数・形式・サイズ不正） | 不能 | 同上。写真を撮り直してもらう |
| 写真の 404（点検結果なし） | 不能 | 同上。結果送信済なのに見つからないのはサーバ側の異常なので、ERROR ログを出す |

| メッセージ ID | 文言 |
|---|---|
| M01-201 | 送信できなかった点検があります。内容を確認して保存し直してください |

## ログ

- 1 回の実行ごとに、契機・対象件数・成功件数・失敗件数を端末ログに出す。
- 回復不能なエラーは、localId・idempotencyKey・応答の code を ERROR で出す（点検内容とコメントは出さない）。
